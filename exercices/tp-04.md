# TP 4 — Étendre un volume logique et créer un volume BTRFS avec snapshot

> Module : 3 — Stockage avancé : LVM et BTRFS
> Durée estimée : 1h30
> Difficulté : 3 / 5
> Type : Travaux pratiques guidés

## Mise en situation

Sur le serveur applicatif, le LV `/srv/app` est presque plein. Vous devez l'étendre à chaud sans démontage. Par ailleurs, l'équipe veut tester BTRFS pour les données du service de partage : volumes, snapshots avant chaque déploiement, compression activée.

## Objectifs

- Étendre un Volume Group puis un Logical Volume à chaud
- Étendre le système de fichiers ext4 sans démonter
- Créer un FS BTRFS avec subvolumes, compression et snapshot

## Prérequis techniques

### Logiciels à installer

- VM Linux avec quatre disques : un disque système (déjà installé) + trois disques additionnels de 5 Go (`/dev/sdb`, `/dev/sdc`, `/dev/sdd`)
- Paquets : `lvm2`, `btrfs-progs`, `parted`

### Vérification de l'environnement

```bash
sudo apt install -y lvm2 btrfs-progs parted btrfs-compsize
lsblk
sudo pvs && sudo vgs && sudo lvs
```

Confirmer la présence de `sdb`, `sdc`, `sdd` non utilisés.

## Architecture cible

```
LVM
  PV : /dev/sdb (5G)         puis ajout de /dev/sdc (5G)
  VG : vg_lab
  LV : lv_app (3G ext4)      puis 7G après extension
  Mount : /srv/app           ext4, monté via fstab

BTRFS
  PV : /dev/sdd (5G)
  Mount : /mnt/data
  Subvolumes : /mnt/data/projets, /mnt/data/backups
  Snapshot ro : /mnt/data/projets-<date>
```

## Étapes

### Étape 1 — Préparer le LVM initial (15 min)

Objectif : avoir un LV ext4 monté sur `/srv/app` à étendre ensuite.

1. Créer le PV, le VG et le LV :
   ```bash
   sudo pvcreate /dev/sdb
   sudo vgcreate vg_lab /dev/sdb
   sudo lvcreate -n lv_app -L 3G vg_lab
   sudo mkfs.ext4 -L app /dev/vg_lab/lv_app
   ```

2. Monter et persister :
   ```bash
   sudo mkdir -p /srv/app
   echo "/dev/vg_lab/lv_app /srv/app ext4 defaults 0 2" | sudo tee -a /etc/fstab
   sudo mount -a
   df -h /srv/app
   ```

3. Créer un fichier témoin :
   ```bash
   sudo dd if=/dev/zero of=/srv/app/file.bin bs=1M count=200
   df -h /srv/app
   ```

Point de contrôle : `mount | grep /srv/app` montre le LV monté.

### Étape 2 — Étendre le LV à chaud (15 min)

Objectif : passer de 3G à 7G sans démonter.

1. Ajouter un PV au VG :
   ```bash
   sudo pvcreate /dev/sdc
   sudo vgextend vg_lab /dev/sdc
   sudo vgs
   ```

2. Étendre le LV de 4G :
   ```bash
   sudo lvextend -L +4G /dev/vg_lab/lv_app
   sudo lvs
   ```

3. Étendre le FS ext4 sans démonter :
   ```bash
   sudo resize2fs /dev/vg_lab/lv_app
   df -h /srv/app
   ls /srv/app/file.bin
   ```

Point de contrôle : `df -h` montre ~7G total, le fichier témoin est intact.

### Étape 3 — Snapshot LVM pour sauvegarde (10 min)

Objectif : faire une sauvegarde cohérente.

1. Créer le snapshot :
   ```bash
   sudo lvcreate -L 1G -s -n snap_app /dev/vg_lab/lv_app
   sudo lvs
   ```

2. Le monter en lecture seule et faire un tar :
   ```bash
   sudo mkdir /mnt/snap_app
   sudo mount -o ro /dev/vg_lab/snap_app /mnt/snap_app
   sudo tar czf /tmp/app-backup.tgz -C /mnt/snap_app .
   ls -lh /tmp/app-backup.tgz
   ```

3. Démonter et supprimer le snapshot :
   ```bash
   sudo umount /mnt/snap_app
   sudo rmdir /mnt/snap_app
   sudo lvremove -y /dev/vg_lab/snap_app
   ```

Point de contrôle : la backup `app-backup.tgz` existe et le snapshot est supprimé.

### Étape 4 — Mettre en oeuvre BTRFS (20 min)

Objectif : un FS BTRFS compressé avec subvolumes.

1. Créer le FS et le monter :
   ```bash
   sudo mkfs.btrfs -L data /dev/sdd
   sudo mkdir -p /mnt/data
   echo "LABEL=data /mnt/data btrfs compress=zstd:3,noatime 0 0" | sudo tee -a /etc/fstab
   sudo mount -a
   sudo btrfs filesystem show
   ```

2. Créer deux subvolumes :
   ```bash
   sudo btrfs subvolume create /mnt/data/projets
   sudo btrfs subvolume create /mnt/data/backups
   sudo btrfs subvolume list /mnt/data
   ```

3. Y mettre du contenu et vérifier la compression :
   ```bash
   sudo cp -r /etc /mnt/data/projets/etc-snap
   sudo btrfs filesystem du /mnt/data/projets/etc-snap | head
   sudo compsize /mnt/data/projets/etc-snap
   ```

Point de contrôle : `btrfs subvolume list` affiche les deux subvolumes.

### Étape 5 — Snapshot BTRFS avant changement (10 min)

Objectif : prendre un snapshot read-only daté, modifier, comparer.

1. Snapshot avant :
   ```bash
   DATE=$(date +%Y%m%d-%H%M)
   sudo btrfs subvolume snapshot -r \
       /mnt/data/projets /mnt/data/projets-$DATE
   sudo btrfs subvolume list /mnt/data
   ```

2. Modifier un fichier :
   ```bash
   sudo bash -c 'echo "modif" > /mnt/data/projets/etc-snap/hostname'
   # `sudo` obligatoire : /etc a ete copie avec ses droits d'origine, certains
   # fichiers sont en 0600 root. Sans sudo, diff sort en code 2 (erreur d'acces)
   # et le `|| echo` affiche "diff detectee" alors que RIEN n'a ete compare.
   sudo diff /mnt/data/projets-$DATE/etc-snap/hostname \
        /mnt/data/projets/etc-snap/hostname || echo "diff détectée"
   ```

3. Restaurer un fichier depuis le snapshot :
   ```bash
   sudo cp /mnt/data/projets-$DATE/etc-snap/hostname \
       /mnt/data/projets/etc-snap/hostname
   sudo diff /mnt/data/projets-$DATE/etc-snap/hostname \
        /mnt/data/projets/etc-snap/hostname && echo "OK"
   ```

Point de contrôle : la diff disparaît après restauration.

### Étape 6 — Maintenance BTRFS (10 min)

1. Vérifier l'occupation et les chunks :
   ```bash
   sudo btrfs filesystem usage /mnt/data
   sudo btrfs filesystem df /mnt/data
   ```

2. Lancer un scrub :
   ```bash
   sudo btrfs scrub start /mnt/data
   sudo btrfs scrub status /mnt/data
   ```

3. Supprimer le snapshot quand c'est fini :
   ```bash
   sudo btrfs subvolume delete /mnt/data/projets-$DATE
   ```

Point de contrôle : `scrub status` indique 0 erreur.
