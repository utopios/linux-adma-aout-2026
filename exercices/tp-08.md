# TP 8 — Configurer une interface réseau, un bonding et un VLAN

> Module : 5 — Maintenance système et configuration réseau
> Durée estimée : 1h
> Difficulté : 3 / 5
> Type : Travaux pratiques guidés

## Mise en situation

Le datacenter migre vers une infrastructure où chaque serveur est connecté en LACP (802.3ad) à deux interfaces de switch, et où les services sont segmentés par VLAN. Vous devez préparer la configuration réseau cible d'un serveur Debian 12 : bonding sur deux NIC, VLAN 42 pour la gestion, VLAN 100 pour la production, le tout persistant.

## Objectifs

- Maîtriser `ip` et `ss` pour l'inspection
- Configurer un bonding 802.3ad et le rendre persistant via systemd-networkd
- Ajouter deux VLAN par-dessus le bonding et y mettre des adresses IP

## Prérequis techniques

### Logiciels à installer

- VM Linux Debian 12 avec **trois** interfaces réseau attachées : `enp1s0` (admin), `enp7s0` et `enp8s0` (à bonder)
- Paquets : `iproute2`, `vlan`, `systemd-networkd`
- Switch ou hyperviseur supportant le LACP (sur VirtualBox, utiliser le mode "Internal Network" pour les deux interfaces de bond)

### Vérification de l'environnement

```bash
sudo apt install -y vlan
ip -br link
lsmod | grep -E "bonding|8021q"
```

## Architecture cible

```
enp7s0 ----+
           +--- bond0 (802.3ad)
enp8s0 ----+        |
                    +--- bond0.42  (admin: 10.0.42.10/24)
                    +--- bond0.100 (prod : 10.0.100.10/24)

enp1s0  -- gardée pour récupération SSH (192.168.56.10/24 fixe)
```

## Étapes

### Étape 1 — Préparer l'environnement (5 min)

Objectif : avoir tous les modules chargés et une interface de secours.

1. Charger les modules :
   ```bash
   sudo modprobe bonding
   sudo modprobe 8021q
   echo "bonding" | sudo tee /etc/modules-load.d/bonding.conf
   echo "8021q"   | sudo tee /etc/modules-load.d/8021q.conf
   ```

2. Vérifier que `enp1s0` (interface de secours) est joignable :
   ```bash
   ip a show enp1s0
   ip route
   ```

Point de contrôle : SSH sur l'IP de secours fonctionne depuis le poste formateur.

### Étape 2 — Créer le bond manuellement (10 min)

Objectif : valider la connectivité avant de basculer en config persistante.

1. Détacher les deux NIC (au cas où elles auraient une IP) :
   ```bash
   sudo ip link set enp7s0 down
   sudo ip link set enp8s0 down
   sudo ip addr flush dev enp7s0
   sudo ip addr flush dev enp8s0
   ```

2. Créer le bond :
   ```bash
   sudo ip link add bond0 type bond mode 802.3ad miimon 100 lacp_rate fast
   sudo ip link set enp7s0 master bond0
   sudo ip link set enp8s0 master bond0
   sudo ip link set enp7s0 up
   sudo ip link set enp8s0 up
   sudo ip link set bond0 up
   ```

3. Vérifier l'agrégation :
   ```bash
   cat /proc/net/bonding/bond0 | head -30
   ip -br link
   ```

Point de contrôle : `bond0` est `UP`, les deux slaves sont `UP`, le mode est `802.3ad`.

### Étape 3 — Ajouter les VLAN (10 min)

Objectif : VLAN 42 et VLAN 100 sur le bond.

1. Créer les sous-interfaces VLAN :
   ```bash
   sudo ip link add link bond0 name bond0.42  type vlan id 42
   sudo ip link add link bond0 name bond0.100 type vlan id 100
   sudo ip link set bond0.42 up
   sudo ip link set bond0.100 up
   ```

2. Affecter les IP :
   ```bash
   sudo ip addr add 10.0.42.10/24  dev bond0.42
   sudo ip addr add 10.0.100.10/24 dev bond0.100
   ```

3. Tester :
   ```bash
   ip -br addr | grep bond0
   ping -c2 -W1 10.0.42.1   2>/dev/null  || echo "pas de gateway VLAN 42 (normal en lab)"
   ping -c2 -W1 10.0.100.1  2>/dev/null  || echo "pas de gateway VLAN 100 (normal en lab)"
   ```

Point de contrôle : les deux sous-interfaces ont leur IP et sont `UP`.

### Étape 4 — Rendre la config persistante avec systemd-networkd (15 min)

Objectif : que tout soit reconstruit au reboot.

> **Ordre critique.** On ecrit TOUTE la configuration cible AVANT de basculer
> de NetworkManager vers systemd-networkd. Couper NetworkManager alors que
> networkd n'a encore aucun fichier `.network` laisse la machine sans aucune
> interface geree — y compris `enp1s0`, l'interface de secours. En TP a
> distance, c'est la perte d'acces garantie.

1. Preserver d'abord l'interface de secours `enp1s0` :
   ```bash
   sudo tee /etc/systemd/network/05-mgmt.network > /dev/null <<'EOF'
   [Match]
   Name=enp1s0

   [Network]
   Address=192.168.56.10/24
   EOF
   ```

3. Définir le device bond et l'attacher :
   ```bash
   sudo tee /etc/systemd/network/10-bond0.netdev > /dev/null <<'EOF'
   [NetDev]
   Name=bond0
   Kind=bond

   [Bond]
   Mode=802.3ad
   MIIMonitorSec=100ms
   LACPTransmitRate=fast
   EOF

   sudo tee /etc/systemd/network/15-bond0-slave-7.network > /dev/null <<'EOF'
   [Match]
   Name=enp7s0

   [Network]
   Bond=bond0
   EOF

   sudo tee /etc/systemd/network/15-bond0-slave-8.network > /dev/null <<'EOF'
   [Match]
   Name=enp8s0

   [Network]
   Bond=bond0
   EOF
   ```

4. Définir les VLANs et le bond logique :
   ```bash
   sudo tee /etc/systemd/network/20-bond0.network > /dev/null <<'EOF'
   [Match]
   Name=bond0

   [Network]
   VLAN=bond0.42
   VLAN=bond0.100
   LinkLocalAddressing=no
   EOF

   sudo tee /etc/systemd/network/21-vlan42.netdev > /dev/null <<'EOF'
   [NetDev]
   Name=bond0.42
   Kind=vlan

   [VLAN]
   Id=42
   EOF

   sudo tee /etc/systemd/network/22-vlan42.network > /dev/null <<'EOF'
   [Match]
   Name=bond0.42

   [Network]
   Address=10.0.42.10/24
   EOF

   sudo tee /etc/systemd/network/23-vlan100.netdev > /dev/null <<'EOF'
   [NetDev]
   Name=bond0.100
   Kind=vlan

   [VLAN]
   Id=100
   EOF

   sudo tee /etc/systemd/network/24-vlan100.network > /dev/null <<'EOF'
   [Match]
   Name=bond0.100

   [Network]
   Address=10.0.100.10/24
   EOF
   ```

5. Maintenant seulement, basculer de NetworkManager vers systemd-networkd.
   Toute la configuration cible est ecrite : la bascule est reversible.

   ```bash
   sudo systemctl enable --now systemd-networkd systemd-resolved
   sudo ln -sf /run/systemd/resolve/stub-resolv.conf /etc/resolv.conf
   sudo systemctl disable --now NetworkManager 2>/dev/null || true
   ```

6. Recharger et verifier :
   ```bash
   sudo networkctl reload
   sudo systemctl restart systemd-networkd
   networkctl status bond0 bond0.42 bond0.100
   ```

Point de controle : `bond0.42` et `bond0.100` sont `routable` (elles portent une
adresse IP).

`bond0` lui-meme s'affiche en `degraded` ou `carrier`, **et c'est normal** : il
ne porte aucune adresse et le TP lui met `LinkLocalAddressing=no`. `networkctl`
reserve `routable` aux interfaces disposant d'une adresse et d'une route. Ne pas
chercher a « corriger » cet etat.

### Étape 5 — Test de bascule (10 min)

Objectif : verifier que le bonding tient si une NIC tombe.

> **Sans switch LACP, le mode `802.3ad` ne negocie aucun agregat** : le bond
> reste avec un seul port actif et une bascule n'est pas observable. On teste
> donc la bascule sur un bond `active-backup`, qui ne demande rien au switch.
> C'est le mode a retenir quand l'equipement reseau n'est pas maitrise.

1. Creer un bond de test en `active-backup` (sans toucher a `bond0`) :
   ```bash
   sudo ip link add bond9 type bond mode active-backup miimon 100
   sudo ip link set enp7s0 down && sudo ip link set enp7s0 master bond9
   sudo ip link set enp8s0 down && sudo ip link set enp8s0 master bond9
   sudo ip link set enp7s0 up && sudo ip link set enp8s0 up && sudo ip link set bond9 up
   grep -E "Currently Active Slave|MII Status" /proc/net/bonding/bond9
   ```

2. Noter le slave actif, puis le faire tomber :
   ```bash
   sudo ip link set enp7s0 down
   sleep 3
   grep "Currently Active Slave" /proc/net/bonding/bond9
   ```

3. Remonter la NIC et nettoyer :
   ```bash
   sudo ip link set enp7s0 up
   sudo ip link del bond9
   ```

Point de controle : `Currently Active Slave` a change de NIC apres la coupure,
puis le bond reste operationnel. C'est exactement le comportement attendu en
production lorsqu'un lien tombe.

> Ne pas chercher a valider la bascule par un `ping 10.0.42.1` : aucune gateway
> n'existe sur les VLAN du lab (l'etape 3 le signale deja), le ping ne repond
> donc jamais, avant comme apres la coupure.

### Étape 6 — Audit final et reboot test (10 min)

1. Snapshot des fichiers de configuration :
   ```bash
   ls /etc/systemd/network/
   ```

2. Reboot et vérification :
   ```bash
   sudo reboot
   ```
   Au retour :
   ```bash
   ip -br addr | grep -E "bond0|enp"
   networkctl status bond0
   ```

Point de contrôle : tout est reconstruit après reboot, les VLAN ont leur IP.
