# TP 7 — Recovery d'un système Linux à partir d'un environnement de secours

> Module : 5 — Maintenance système et configuration réseau
> Durée estimée : 1h
> Difficulté : 4 / 5
> Type : Travaux pratiques guidés

## Mise en situation

Une mise à jour mal exécutée a cassé la séquence de boot d'un serveur Debian 12 : il boucle au démarrage. Vous disposez d'un live USB SystemRescue (ou d'une ISO Debian en mode live) et d'un accès console à la VM. Vous devez chrooter, identifier le défaut, le corriger, et redémarrer.

## Objectifs

- Démarrer une VM Linux depuis une ISO live
- Monter les partitions et faire un chroot fonctionnel
- Réparer une configuration cassée (initramfs + GRUB)

## Prérequis techniques

### Logiciels à installer

- VM Linux Debian 12 fonctionnelle au départ
- ISO Debian 12 live (ou SystemRescue) attachée comme deuxième CD-ROM
- Possibilité de modifier l'ordre de boot dans la VM

### Vérification de l'environnement

```bash
ls /sys/firmware/efi 2>/dev/null && echo UEFI || echo BIOS
sudo lsblk -f
sudo grep -E 'GRUB_CMDLINE' /etc/default/grub
```

## Architecture cible

```
Avant casse :
  /dev/sda1 EFI    /boot/efi
  /dev/sda2 ext4   /
  /dev/sda3 swap

Casse simulée :
  GRUB_CMDLINE_LINUX="root=UUID=invalide ..."
  initramfs absent ou cassé

Après recovery :
  GRUB régénéré, initramfs reconstruit, boot OK
```

## Étapes

### Étape 1 — Préparer la VM et la casse contrôlée (10 min)

Objectif : provoquer un boot impossible reproductible.

1. Sauvegarder un snapshot de la VM (au niveau hyperviseur).
2. Sur la VM en bon état, casser le boot de manière réversible :
   ```bash
   sudo cp /etc/default/grub /etc/default/grub.bak
   sudo sed -i 's|GRUB_CMDLINE_LINUX_DEFAULT="[^"]*"|GRUB_CMDLINE_LINUX_DEFAULT="root=UUID=00000000-bad-bad-bad-000000000000 quiet"|' /etc/default/grub
   sudo update-grub
   sudo mv /boot/initrd.img-$(uname -r) /boot/initrd.img-$(uname -r).disabled
   ```
3. Reboot pour constater la panne.

Point de contrôle : la VM ne boote plus sur disque (kernel panic ou drop dans initramfs).

### Étape 2 — Démarrer en live et inspecter (10 min)

Objectif : prendre la main avec l'ISO live.

1. Modifier l'ordre de boot pour démarrer sur l'ISO live.
2. Une fois en live :
   ```bash
   sudo lsblk -f
   sudo blkid
   ip a
   ```
3. Identifier la partition root et la partition EFI (ou /boot).

Point de contrôle : vous avez noté UUID, FS et taille de chaque partition utile.

### Étape 3 — Monter et chrooter (15 min)

Objectif : avoir un shell qui agit "comme si" on était dans le système installé.

1. Monter le rootfs :
   ```bash
   sudo mkdir -p /mnt/sys-target
   sudo mount /dev/sda2 /mnt/sys-target
   ```

2. Si EFI : monter `/boot/efi` aussi :
   ```bash
   sudo mount /dev/sda1 /mnt/sys-target/boot/efi
   ```

3. Bind-mounts requis pour le chroot :
   ```bash
   for d in dev proc sys run; do
     sudo mount --bind /$d /mnt/sys-target/$d
   done
   ```

4. Chroot :
   ```bash
   sudo chroot /mnt/sys-target /bin/bash
   ```

5. Dans le chroot, vérifier :
   ```bash
   uname -a
   ls /boot
   cat /etc/debian_version
   ```

Point de contrôle : le prompt indique le hostname installé et `cat /etc/debian_version` retourne la bonne version.

### Étape 4 — Réparer (10 min)

Objectif : restaurer la commande noyau correcte et l'initramfs.

1. Restaurer GRUB cmdline :
   ```bash
   mv /etc/default/grub.bak /etc/default/grub || true
   grep GRUB_CMDLINE /etc/default/grub
   ```

2. Reconstruire l'initramfs :
   ```bash
   ls /boot/initrd*.disabled 2>/dev/null && \
       mv /boot/initrd.img-$(ls /lib/modules | head -1).disabled \
          /boot/initrd.img-$(ls /lib/modules | head -1)
   update-initramfs -u -k all
   ls -lh /boot/initrd*
   ```

3. Régénérer GRUB :
   ```bash
   update-grub
   grep -E "menuentry|initrd|linux" /boot/grub/grub.cfg | head -10
   ```

4. (Si GRUB EFI absent) Réinstaller :
   ```bash
   grub-install --target=x86_64-efi --efi-directory=/boot/efi --bootloader-id=debian
# sur la VM de demo du formateur (ARM64) : --target=arm64-efi
   ```

Point de contrôle : `/boot/initrd.img-*` existe et `grub.cfg` contient les bonnes UUID.

### Étape 5 — Sortir et redémarrer (5 min)

1. Sortir du chroot :
   ```bash
   exit
   ```

2. Démonter dans l'ordre inverse :
   ```bash
   for d in run sys proc dev; do
     sudo umount /mnt/sys-target/$d
   done
   sudo umount /mnt/sys-target/boot/efi 2>/dev/null
   sudo umount /mnt/sys-target
   ```

3. Détacher l'ISO live et rebooter sur disque.

Point de contrôle : la VM boote normalement et atteint le login.

### Étape 6 — Audit post-incident (10 min)

Objectif : tracer ce qui s'est passé.

Une fois revenu sur le système :

```bash
journalctl -b 0 -p err --no-pager | head
journalctl -b -1 -p err --no-pager | head
ls -lh /boot/
sudo update-initramfs -k all -u
```

Rédiger un mini post-mortem :

- Date et durée de l'incident
- Symptôme exact
- Cause racine
- Actions de correction
- Mesure préventive (snapshot avant `update-grub`, lecture de `grub.cfg` avant reboot)

Point de contrôle : le post-mortem tient sur une page et conclut sur une mesure préventive concrète.
