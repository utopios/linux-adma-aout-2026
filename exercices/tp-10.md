# TP 10 — Durcissement d'un serveur Linux selon une checklist

> Module : 6 — Performances et sécurité
> Durée estimée : 1h
> Difficulté : 3 / 5
> Type : Travaux pratiques guidés

## Mise en situation

Le RSSI demande à ce que tout serveur Linux exposé applique un socle minimum de durcissement avant ouverture au réseau. Vous devez, sur une VM, appliquer une checklist : SSH, sudo, sysctl, pare-feu, audit minimal, et fournir un rapport de conformité.

## Objectifs

- Appliquer un durcissement SSH (clés, no-root, no-password, timeout)
- Restreindre `sudo` et la politique de mots de passe
- Activer un pare-feu (`nftables` ou `ufw`)
- Appliquer un set de paramètres `sysctl` sécurité

## Prérequis techniques

### Logiciels à installer

- VM Linux (Debian 12 ou Ubuntu 22.04+) propre, accès sudo
- Une clé SSH publique sur votre poste (`~/.ssh/id_ed25519.pub`)
- Paquets : `openssh-server`, `sudo`, `nftables` (ou `ufw`), `auditd`, `unattended-upgrades`, `libpam-pwquality`

### Vérification de l'environnement

```bash
sudo apt update
sudo apt install -y openssh-server sudo nftables auditd \
    unattended-upgrades libpam-pwquality
ssh-keygen -lf ~/.ssh/id_ed25519.pub  # côté poste
```

## Architecture cible

```
Utilisateur dédié : admin
SSH:
  port 22, key only, no root, MaxAuthTries 3, ClientAliveInterval 300
sudo: NOPASSWD ciblé, pas de ALL=(ALL) NOPASSWD:ALL
sysctl: /etc/sysctl.d/99-hardening.conf
nftables: input drop, autorise loopback, established, ssh
auditd: actif et persisté
unattended-upgrades: security uniquement
```

## Étapes

### Étape 1 — Compte admin et clé SSH (10 min)

Objectif : pouvoir se logger en non-root, par clé.

1. Créer le compte :
   ```bash
   sudo adduser --gecos "Admin" admin
   sudo usermod -aG sudo admin
   ```

2. Installer la clé publique :
   ```bash
   sudo install -d -o admin -g admin -m 700 /home/admin/.ssh
   sudo install -o admin -g admin -m 600 /dev/stdin /home/admin/.ssh/authorized_keys <<< "$(cat ~/.ssh/id_ed25519.pub)"
   ```

3. Tester depuis le poste **avant** de couper le mot de passe :
   ```bash
   ssh admin@<vm-ip>
   ```

Point de contrôle : login admin par clé fonctionne, et `sudo -i` aussi.

### Étape 2 — Durcir SSH (10 min)

Objectif : pas de root, pas de mot de passe, timeout court.

1. Créer un fichier de surcharge plutôt que d'éditer `sshd_config` :
   ```bash
   sudo tee /etc/ssh/sshd_config.d/99-hardening.conf > /dev/null <<'EOF'
   PermitRootLogin no
   PasswordAuthentication no
   KbdInteractiveAuthentication no
   PubkeyAuthentication yes
   MaxAuthTries 3
   LoginGraceTime 30s
   AllowUsers admin
   ClientAliveInterval 300
   ClientAliveCountMax 2
   X11Forwarding no
   AllowTcpForwarding no
   EOF
   ```

2. Vérifier la syntaxe et recharger :
   ```bash
   sudo sshd -t
   sudo systemctl reload ssh
   ```

3. Tester (depuis une autre console) que `root` ne peut plus se logger et que le password est refusé.

Point de contrôle : `ssh root@<vm>` est refusé, `ssh admin@<vm>` fonctionne par clé.

### Étape 3 — Sudo granulaire et politique mot de passe (10 min)

Objectif : ne pas laisser `ALL=(ALL) NOPASSWD:ALL`.

1. Mettre une règle ciblée :
   ```bash
   sudo tee /etc/sudoers.d/admin > /dev/null <<'EOF'
   admin ALL=(root) NOPASSWD: /usr/bin/systemctl reload nginx, /usr/bin/journalctl
   Defaults:admin timestamp_timeout=5
   EOF
   sudo visudo -c
   ```

2. Politique de mots de passe :
   ```bash
   sudo tee /etc/security/pwquality.conf.d/00-hardening.conf > /dev/null <<'EOF'
   minlen = 14
   minclass = 3
   maxrepeat = 3
   maxsequence = 3
   dcredit = -1
   ucredit = -1
   lcredit = -1
   ocredit = -1
   EOF
   ```

3. Forcer expiration sur un compte test :
   ```bash
   sudo chage -M 90 -m 7 -W 14 admin
   sudo chage -l admin
   ```

Point de contrôle : `visudo -c` retourne OK, `chage -l admin` montre l'expiration.

### Étape 4 — sysctl sécurité (5 min)

```bash
sudo tee /etc/sysctl.d/99-hardening.conf > /dev/null <<'EOF'
# Kernel
kernel.kptr_restrict=2
kernel.dmesg_restrict=1
kernel.unprivileged_bpf_disabled=2
kernel.kexec_load_disabled=1

# Filesystem
fs.protected_hardlinks=1
fs.protected_symlinks=1
fs.protected_fifos=2
fs.protected_regular=2
fs.suid_dumpable=0

# IPv4
net.ipv4.conf.all.rp_filter=1
net.ipv4.conf.default.rp_filter=1
net.ipv4.conf.all.accept_redirects=0
net.ipv4.conf.all.send_redirects=0
net.ipv4.conf.all.accept_source_route=0
net.ipv4.conf.all.log_martians=1
net.ipv4.tcp_syncookies=1

# IPv6
net.ipv6.conf.all.accept_ra=0
net.ipv6.conf.all.accept_redirects=0
EOF

sudo sysctl --system
```

Point de contrôle : `sysctl kernel.kptr_restrict` retourne `2`.

### Étape 5 — Pare-feu (10 min)

Au choix selon la distribution. Exemple `nftables` :

```bash
sudo tee /etc/nftables.conf > /dev/null <<'EOF'
#!/usr/sbin/nft -f
flush ruleset

table inet filter {
    chain input {
        type filter hook input priority 0; policy drop;
        ct state established,related accept
        iifname "lo" accept
        ct state invalid drop

        ip protocol icmp limit rate 5/second accept
        ip6 nexthdr icmpv6 accept

        tcp dport 22 ct state new accept
    }
    chain forward {
        type filter hook forward priority 0; policy drop;
    }
    chain output {
        type filter hook output priority 0; policy accept;
    }
}
EOF

sudo systemctl enable --now nftables
sudo nft list ruleset
```

Point de contrôle : depuis le poste, le SSH passe ; un `nc -zv <vm> 80` est refusé.

### Étape 6 — Audit et mises à jour (10 min)

1. Activer auditd :
   ```bash
   sudo systemctl enable --now auditd
   sudo tee -a /etc/audit/rules.d/00-hardening.rules > /dev/null <<'EOF'
   -w /etc/passwd -p wa -k passwd_changes
   -w /etc/shadow -p wa -k shadow_changes
   -w /etc/sudoers -p wa -k sudoers_changes
   -w /var/log/auth.log -p wa -k auth_log
   EOF
   sudo augenrules --load
   sudo systemctl restart auditd
   ```

2. Activer les MAJ sécurité automatiques :
   ```bash
   sudo dpkg-reconfigure -plow unattended-upgrades || true
   sudo tee /etc/apt/apt.conf.d/20auto-upgrades > /dev/null <<'EOF'
   APT::Periodic::Update-Package-Lists "1";
   APT::Periodic::Unattended-Upgrade "1";
   EOF
   ```

3. Tester un déclenchement manuel :
   ```bash
   sudo unattended-upgrade --dry-run --debug | head -20
   ```

Point de contrôle : `systemctl is-active auditd` retourne `active`, `unattended-upgrade --dry-run` ne renvoie pas d'erreur.

### Étape 7 — Rapport de conformité (5 min)

Créer `/root/hardening-report.md` qui répond à la checklist :

```markdown
# Rapport de durcissement — <hostname> — <date>

| Item | État | Preuve |
|------|------|--------|
| SSH PermitRootLogin no | OK | extrait sshd_config.d |
| SSH PasswordAuthentication no | OK | extrait |
| sudo non générique NOPASSWD | OK | sudoers.d/admin |
| Politique pwquality minlen=14 | OK | pwquality.conf.d |
| sysctl hardening appliqué | OK | sysctl --system |
| nftables actif, default drop | OK | nft list ruleset |
| auditd actif | OK | systemctl is-active |
| unattended-upgrades activé | OK | 20auto-upgrades |

Mesures à compléter ultérieurement : MFA, SELinux/AppArmor enforcing, supervision centralisée.
```
