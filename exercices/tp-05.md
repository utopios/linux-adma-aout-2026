# TP 5 — Amorçage avancé : rescue, emergency, reset root, mesure systemd

> Module : 4 — Séquence d'amorçage et gestion de l'activité
> Durée estimée : 1h
> Difficulté : 3 / 5
> Type : Travaux pratiques guidés

## Mise en situation

Avant un déploiement majeur, l'équipe veut s'assurer que chaque administrateur sait remettre la main sur un serveur qui ne boote pas. Vous allez réaliser sur une VM les manoeuvres types : passer en rescue, en emergency, réinitialiser le mot de passe root, puis analyser le temps de démarrage.

## Objectifs

- Démarrer en mode rescue puis emergency depuis le bootloader
- Réinitialiser le mot de passe root depuis GRUB
- Mesurer le temps de boot et identifier les services lents

## Prérequis techniques

### Logiciels à installer

- VM Linux (Debian 12 ou Ubuntu 22.04+) avec GRUB 2 et systemd
- Accès console à la VM (pas seulement SSH)
- Pouvoir redémarrer librement la VM

### Vérification de l'environnement

```bash
ls /sys/firmware/efi 2>/dev/null && echo UEFI || echo BIOS
cat /etc/default/grub | grep TIMEOUT
systemctl get-default
```

## Architecture cible

```
GRUB
  Edition d'entrée (touche e) :
    + systemd.unit=rescue.target
    + systemd.unit=emergency.target
    + init=/bin/bash             (reset root)

systemd
  multi-user.target  (par défaut)
  rescue.target      (mono-user, FS montés)
  emergency.target   (rootfs RO, services off)
```

## Étapes

### Étape 1 — Préparer GRUB (5 min)

Objectif : avoir le temps de voir le menu et d'éditer une entrée.

1. Allonger le timeout et désactiver le hidden menu :
   ```bash
   sudo cp /etc/default/grub /etc/default/grub.bak
   sudo sed -i 's/^GRUB_TIMEOUT=.*/GRUB_TIMEOUT=5/' /etc/default/grub
   sudo sed -i 's/^GRUB_TIMEOUT_STYLE=.*/GRUB_TIMEOUT_STYLE=menu/' /etc/default/grub
   grep -E "TIMEOUT" /etc/default/grub
   sudo update-grub
   ```

2. Redémarrer la VM et vérifier que le menu GRUB s'affiche pendant 5s.

Point de contrôle : le menu GRUB est visible avec au moins une entrée Linux.

### Étape 2 — Mode rescue (10 min)

Objectif : démarrer dans `rescue.target`.

1. Au menu GRUB, sélectionner l'entrée Linux et taper `e`.
2. Localiser la ligne commençant par `linux` et ajouter à la fin : `systemd.unit=rescue.target`.
3. `Ctrl+x` pour booter.
4. Saisir le mot de passe root quand demandé.
5. Vérifier l'environnement :
   ```bash
   systemctl status
   systemctl get-default
   mount | head
   ```
6. Revenir à la cible normale :
   ```bash
   systemctl default
   ```

Point de contrôle : la VM passe en multi-user, login normal disponible.

### Étape 3 — Mode emergency (10 min)

Objectif : démarrer dans `emergency.target` (rootfs RO, peu de services).

1. Au prochain reboot, GRUB → `e` → ajouter `systemd.unit=emergency.target` → `Ctrl+x`.
2. Saisir le mot de passe root.
3. Constater :
   ```bash
   mount | head -3            # / monté en RO
   systemctl list-units --type=service --state=active
   ```
4. Remonter `/` en RW pour faire un changement test :
   ```bash
   mount -o remount,rw /
   touch /root/emergency-test
   ```
5. Sortir vers la cible normale :
   ```bash
   systemctl default
   ```

Point de contrôle : à la sortie, `/root/emergency-test` existe sur le système redémarré.

### Étape 4 — Réinitialisation du mot de passe root (10 min)

Objectif : accéder à un shell sans mot de passe et changer le mot de passe root.

1. Avant le test, choisir un mot de passe alternatif que vous appliquerez.
2. Reboot, GRUB → `e` → sur la ligne `linux` :
   - Remplacer la fin par `init=/bin/bash`
   - Garder `ro` ou ajouter
3. `Ctrl+x` pour booter.
4. Une fois au prompt `bash` :
   ```bash
   mount -o remount,rw /
   passwd
   sync
   exec /sbin/init
   ```
5. Au login normal, vérifier que le nouveau mot de passe fonctionne.

Point de contrôle : login root réussi avec le nouveau mot de passe.

### Étape 5 — Mesurer et analyser le boot (15 min)

Objectif : utiliser `systemd-analyze`.

1. Vue globale :
   ```bash
   systemd-analyze
   systemd-analyze blame | head -15
   systemd-analyze critical-chain
   ```

2. Diagramme :
   ```bash
   systemd-analyze plot > /tmp/boot.svg
   ls -lh /tmp/boot.svg
   ```
   Récupérer le SVG via SCP pour l'inspecter visuellement.

3. Identifier deux services qui prennent plus de 3 secondes et noter leur nom et leur temps.

Point de contrôle : `systemd-analyze blame | head -3` montre les 3 plus lents avec une durée.
